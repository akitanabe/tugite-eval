## 新しい期待

意味ある処理単位ごとに実コードをまとまった抜粋で示し、何をしているかを短く補足する。
位置名一覧や長い散文だけでは達成としない。単なる全コードdumpも目的ではない。
まとまった抜粋は一つの関数全体に限定しない。一つの関数内の複数処理を分けることも、
複数関数/ファイルから一つの意味ある処理を説明することも許す。その場合は出典と省略を明示する。
架空の合成関数・擬似コードを実在と偽らない。注釈・図・短い接続説明も許すが、主な実コード抜粋の代替にはしない。

目的は自分で実装していないHumanが処理間のつながりをコードで追えること。
入力値→判断/変更→次へ渡す値・呼出先を読み順に追えるように選び、孤立した抜粋列挙にしない。
文章は接続と省略を補助し、全呼出しdumpに戻さない。

抜粋の必要十分性を、重要な判断・順序・状態・データ受渡し・副作用・tx・失敗・接続を追えるかで評価する。
抜粋の行数、fence数、文量比率、特定の章立て・語句・唯一の抜粋集合をoracleにしない。
短い回帰fixtureでは全関数が必要十分な抜粋になり得るため、全関数提示を機械的にdumpと扱わない。
未提供adapterや実装のない接続をコードで補わせない。

さらにユーザーは「引数とかもゼロイチで全て解説する必要はありません。あくまで内部で行っている処理に絞ってください」と範囲を明確化した。
引数一覧・型・デフォルト値・全入力の網羅説明を追加しない。値/引数の補足は内部の重要な分岐・状態変更・受渡しを
理解するために必要な箇所だけ、コードに沿って短く示す。入力から出力までの接続説明をAPIリファレンス化しない。
引数解説の量によって加点しない。この補足も新candidate到着前の仕様入力として記録する。

追加の粒度優先順位として、見て分かる引数や単純代入の逐語説明へ情報を割かず、コードをまたぐ接続、
重要な分岐・状態変化・実行順序へ説明量を集中する。コードを読む理解を補助し、一行ずつ日本語へ翻訳しない。
ユーザーの原文「そうですね、引数とかの見てわかるものに情報をあまり割かないでください。コ」の
末尾「コ」は未完として保持し、補完しない。接続等への集中は親の明示補足として記録し、
新たな網羅項目や文量の機械判定を増やすものではない。
